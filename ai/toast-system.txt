TOAST NOTIFICATION SYSTEM
=========================

CRITICAL: Two toast systems - Declarative Toast component vs Programmatic Toast Service

TOAST SERVICE (RECOMMENDED)
---------------------------
import { toast, ToastContainer } from "svelte-fluentui"

Store-based programmatic API for showing toasts from anywhere in your app.

BASIC SETUP
-----------
Add ToastContainer once in root layout:

// +layout.svelte
<script>
import "svelte-fluentui/styles.scss"
import { ToastContainer } from "svelte-fluentui"
</script>

<ToastContainer />

<slot />  <!-- Your pages render here -->

SHOWING TOASTS
--------------
import { toast } from "svelte-fluentui"

// Success toast
toast.success("Operation completed successfully!")

// Error toast
toast.error("Something went wrong!")

// Warning toast
toast.warning("Please review your input")

// Info toast
toast.info("New update available")

TOAST OPTIONS
-------------
toast.success(message, options)

Options:
duration?: number        // Auto-dismiss time (ms), default: 5000
persistent?: boolean     // Never auto-dismiss, default: false
position?: ToastPosition // Position on screen
showProgress?: boolean   // Show progress bar, default: false

Positions:
"top-right"     // Default
"top-left"
"top-center"
"bottom-right"
"bottom-left"
"bottom-center"

EXAMPLES
--------
Auto-dismiss after 3 seconds:
toast.success("Saved!", { duration: 3000 })

Persistent toast (manual dismiss only):
toast.error("Critical error!", { persistent: true })

With progress bar:
toast.info("Processing...", {
    duration: 10000,
    showProgress: true
})

Custom position:
toast.success("Message sent!", { position: "bottom-right" })

TOAST SERVICE METHODS
---------------------
Show toast:
toast.success(message, options)
toast.error(message, options)
toast.warning(message, options)
toast.info(message, options)

Dismiss specific toast:
const id = toast.success("Processing...")
toast.dismiss(id)

Dismiss all toasts:
toast.dismissAll()

TOAST ID
--------
Each toast returns an ID for later dismissal:

const toastId = toast.info("Loading...")

// Later, dismiss it
setTimeout(() => {
    toast.dismiss(toastId)
}, 2000)

TOASTCONTAINER PROPS
--------------------
<ToastContainer
    position="top-right"
    maxToasts={5}
/>

Props:
position?: ToastPosition   // Default position for toasts
maxToasts?: number         // Max simultaneous toasts (default: 5)

COMPLETE TOAST SERVICE EXAMPLE
-------------------------------
<script>
import { Button, Stack, toast } from "svelte-fluentui"

async function saveData() {
    const toastId = toast.info("Saving...", { persistent: true })

    try {
        const response = await fetch("/api/save", { method: "POST" })

        if (response.ok) {
            toast.dismiss(toastId)
            toast.success("Saved successfully!")
        } else {
            toast.dismiss(toastId)
            toast.error("Failed to save")
        }
    } catch (error) {
        toast.dismiss(toastId)
        toast.error("Network error")
    }
}

function showProgress() {
    toast.info("Processing file...", {
        duration: 10000,
        showProgress: true
    })
}
</script>

<Stack orientation="horizontal" gap="0.5rem">
    <Button onclick={() => toast.success("Success!")}>
        Success
    </Button>
    <Button onclick={() => toast.error("Error!")}>
        Error
    </Button>
    <Button onclick={() => toast.warning("Warning!")}>
        Warning
    </Button>
    <Button onclick={() => toast.info("Info!")}>
        Info
    </Button>
    <Button onclick={saveData}>
        Save with Loading
    </Button>
    <Button onclick={showProgress}>
        Show Progress
    </Button>
    <Button onclick={() => toast.dismissAll()}>
        Dismiss All
    </Button>
</Stack>

DECLARATIVE TOAST (BASIC)
--------------------------
import { Toast } from "svelte-fluentui"

Inline toast component (less common use case):

<Toast
    message="This is a toast"
    intent="success"
    visible={true}
/>

Props:
message: string
intent?: "success" | "error" | "warning" | "info"
visible?: boolean
position?: ToastPosition
duration?: number
persistent?: boolean
showProgress?: boolean

Example:
<script>
let showToast = $state(false)

function triggerToast() {
    showToast = true
    setTimeout(() => showToast = false, 5000)
}
</script>

{#if showToast}
    <Toast
        message="Action completed!"
        intent="success"
        visible={showToast}
        position="top-right"
    />
{/if}

<Button onclick={triggerToast}>Show Toast</Button>

TOAST SERVICE VS DECLARATIVE
-----------------------------
Toast Service (Recommended):
✅ Call from anywhere (actions, utils, API calls)
✅ No prop drilling
✅ Centralized management
✅ Auto-cleanup
✅ Position stacking
✅ Simpler API

Declarative Toast:
✅ Works without store
✅ Component-based
❌ Requires state management
❌ Limited to component scope
❌ More boilerplate

WHEN TO USE EACH
----------------
Use Toast Service when:
- Showing toasts from event handlers
- Showing toasts from async functions
- Showing toasts from utility functions
- Need to dismiss programmatically
- Want centralized toast management

Use Declarative Toast when:
- Need full control over toast lifecycle
- Building custom toast wrapper
- Avoiding global state
- Need SSR compatibility

TOAST STACKING
--------------
ToastContainer automatically stacks multiple toasts:

toast.success("First")
toast.info("Second")
toast.warning("Third")

All toasts appear stacked at the configured position.

Max toasts limit:
<ToastContainer maxToasts={3} />

If 3 toasts shown, oldest is removed when 4th appears.

TOAST POSITIONS
---------------
Different positions for different use cases:

Top positions (less intrusive):
- top-right: Default, status updates
- top-center: Important announcements
- top-left: Alternative to top-right

Bottom positions (more noticeable):
- bottom-right: Form validation errors
- bottom-center: Critical warnings
- bottom-left: Alternative to bottom-right

<ToastContainer position="bottom-right" />

Or per-toast:
toast.error("Error!", { position: "bottom-center" })

TOAST DURATION
--------------
Default duration: 5000ms (5 seconds)

Short toasts (quick actions):
toast.success("Copied!", { duration: 2000 })

Long toasts (important messages):
toast.warning("Please review...", { duration: 10000 })

Persistent (critical errors):
toast.error("Connection lost", { persistent: true })

PROGRESS BAR
------------
Show progress for long operations:

toast.info("Uploading file...", {
    duration: 30000,
    showProgress: true
})

Progress bar animates from 100% to 0% over duration.

INTEGRATION PATTERNS
--------------------
Form submission:
async function handleSubmit() {
    try {
        const response = await fetch("/api/submit", {
            method: "POST",
            body: JSON.stringify(formData)
        })

        if (response.ok) {
            toast.success("Form submitted successfully!")
        } else {
            toast.error("Submission failed. Please try again.")
        }
    } catch (error) {
        toast.error("Network error. Check your connection.")
    }
}

API error handling:
async function fetchData() {
    const loadingId = toast.info("Loading data...", { persistent: true })

    try {
        const data = await fetch("/api/data").then(r => r.json())
        toast.dismiss(loadingId)
        return data
    } catch (error) {
        toast.dismiss(loadingId)
        toast.error("Failed to load data")
        throw error
    }
}

Clipboard operations:
async function copyToClipboard(text: string) {
    try {
        await navigator.clipboard.writeText(text)
        toast.success("Copied to clipboard!", { duration: 2000 })
    } catch (error) {
        toast.error("Failed to copy")
    }
}

File upload with progress:
async function uploadFile(file: File) {
    const uploadId = toast.info(`Uploading ${file.name}...`, {
        showProgress: true,
        duration: 10000
    })

    try {
        const formData = new FormData()
        formData.append("file", file)

        const response = await fetch("/api/upload", {
            method: "POST",
            body: formData
        })

        toast.dismiss(uploadId)

        if (response.ok) {
            toast.success(`${file.name} uploaded!`)
        } else {
            toast.error(`Failed to upload ${file.name}`)
        }
    } catch (error) {
        toast.dismiss(uploadId)
        toast.error("Upload failed")
    }
}

Undo actions:
function deleteItem(id: number) {
    // Show toast with undo option
    toast.warning("Item deleted", {
        duration: 5000
    })

    // Actually delete after toast expires
    setTimeout(() => {
        // Perform deletion
        console.log("Deleted:", id)
    }, 5000)
}

MULTIPLE TOASTCONTAINERS
-------------------------
Use multiple containers for different positions:

Then show toasts at specific positions:
toast.success("Status update", { position: "top-right" })
toast.error("Validation error", { position: "bottom-center" })

COMMON TOAST ERRORS
-------------------
Error: "Toasts not appearing"
Fix: Add ToastContainer to layout

❌ toast.success("Message")  // No container
✅ <ToastContainer /> in layout, then toast.success("Message")

Error: "Too many toasts stacking"
Fix: Set maxToasts limit

❌ <ToastContainer />  // Unlimited
✅ <ToastContainer maxToasts={5} />

Error: "Toast not dismissing"
Fix: Check if persistent option used

❌ toast.success("Message", { persistent: true })  // Never dismisses
✅ toast.success("Message", { duration: 5000 })

Error: "Can't dismiss specific toast"
Fix: Save toast ID

❌ toast.success("Loading...")
    toast.dismiss(?)  // No ID saved
✅ const id = toast.success("Loading...")
    toast.dismiss(id)

BEST PRACTICES
--------------
- Add ToastContainer once in root layout
- Use toast service for most cases
- Keep messages concise (< 50 characters)
- Use appropriate intent (success, error, warning, info)
- Set reasonable durations (2-10 seconds)
- Use persistent only for critical errors
- Save toast ID when you need to dismiss it
- Limit max toasts to avoid clutter (5 recommended)
- Use top-right for status updates
- Use bottom-center for errors/warnings
- Show progress for long operations
- Dismiss loading toasts when operation completes
- Test with screen readers
- Provide meaningful error messages
